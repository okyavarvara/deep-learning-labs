# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа `X → Linear(4, 8) → ReLU → Linear(8, 3)` на датасеті Iris. Ручний
backprop реалізовано в NumPy (float64), звірено з PyTorch autograd і
чисельним диференціюванням.

## Структура репозиторію

```
lab1/
├── data.py         # завантаження Iris, стратифікований поділ, стандартизація
├── model.py         # init_params, forward, cross_entropy_loss, backward (ручний)
├── torch_ref.py      # еталонна PyTorch-реалізація для звірки (autograd лише тут)
├── numcheck.py       # чисельне диференціювання центральною різницею
├── main.py           # запуск усіх кроків: --mode correct|buggy|both
├── pyproject.toml     # залежності з фіксованими версіями (uv)
├── uv.lock            # lock-файл uv
└── results.json        # збережені числові результати останнього запуску
```

## Відтворення результатів

```bash
uv sync
uv run python main.py --mode both
```

`--mode correct` (за замовчуванням) виконує правильну реалізацію,
`--mode buggy` — дослід із навмисно пропущеним діленням на N (п. 4),
`--mode both` — обидва послідовно (використано для цього звіту).

## Дані та ініціалізація

- Iris: 150 обʼєктів, 4 ознаки, 3 класи.
- Стратифікований поділ 70/30 (по 35/15 на клас) через `np.random.default_rng(0)`:
  класи перебираються в порядку 0, 1, 2, індекси кожного класу перемішуються,
  перші 35 йдуть у train, решта 15 — у test.
- Стандартизація: `(x - mean) / std` (ddof=0), статистики — лише з train.
- Ініціалізація (один `np.random.default_rng(0)`, послідовно W1, потім W2):
  - `W1` (4×8): He, `N(0, sqrt(2/4))`; `b1` (8,) = 0
  - `W2` (8×3): Xavier, `N(0, sqrt(2/(8+3)))`; `b2` (3,) = 0

## 1. Формули прямого проходу

```
Z1 = X @ W1 + b1        (N,4)@(4,8) + (8,)   -> (N, 8)
A1 = ReLU(Z1) = max(0, Z1)                    -> (N, 8)
Z2 = A1 @ W2 + b2       (N,8)@(8,3) + (3,)   -> (N, 3)   логіти
```

Крос-ентропія через log-softmax зі зсувом на максимум (чисельна стабільність):

```
logp = Z2 - max(Z2, axis=1) - log( sum( exp(Z2 - max(Z2, axis=1)), axis=1 ) )
L = - mean_i( logp[i, y_i] )
```

Для зворотного проходу зберігаються: `X` (N,4), `Z1` (N,8), `A1` (N,8).
`Z2` (N,3) обчислюється, але не входить до кешу, оскільки одразу
використовується для softmax у backward.

## 2. Формули зворотного проходу

Нехай `P = softmax(Z2)` (N,3), `Y` — one-hot мітки (N,3). Похідна
крос-ентропії за логітами (стандартний результат softmax+CE):

```
dZ2 = (P - Y) / N                             (N, 3)

dW2 = A1ᵀ @ dZ2         (8,N)@(N,3) -> (8, 3)
db2 = sum(dZ2, axis=0)                        -> (3,)

dA1 = dZ2 @ W2ᵀ         (N,3)@(3,8) -> (N, 8)
dZ1 = dA1 * 1[Z1 > 0]                          -> (N, 8)   маска ReLU

dW1 = Xᵀ @ dZ1          (4,N)@(N,8) -> (4, 8)
db1 = sum(dZ1, axis=0)                        -> (8,)
```

| Величина | Розмірність |
|---|---|
| dZ2 | (N, 3) |
| dW2, dA1, dZ1, dW1 | (8,3), (N,8), (N,8), (4,8) |
| db2, db1 | (3,), (8,) |

Поділ на `N` у `dZ2` — це похідна усередненої (а не сумарної) крос-ентропії;
саме його прибирають у досліді п. 4.

## 3. Звірка з PyTorch

`torch.nn.Linear` зберігає ваги у формі `(out, in)`, тому при перенесенні
параметрів NumPy `(in, out)` матриці транспонуються (`W1.T`, `W2.T`).
Модель переведено в `float64` **до** копіювання ваг (інакше значення
спершу зрізаються до float32 і звірка штучно провалюється на рівні ~1e-8
замість очікуваного машинного епсилону — цю помилку ми зловили й
виправили під час розробки).

Критерій: `|a - b| ≤ 1e-12`.

| Величина | Максимальна абсолютна різниця NumPy / PyTorch | Перевірку пройдено |
|---|---|---|
| Втрата | 2.22e-16 | Так |
| Градієнт W1 | 5.55e-17 | Так |
| Градієнт b1 | 3.82e-17 | Так |
| Градієнт W2 | 1.11e-16 | Так |
| Градієнт b2 | 1.53e-16 | Так |

Значення втрати:

- NumPy: `1.4562007801142816`
- PyTorch: `1.4562007801142818`

Усі значення скінченні, різниці на рівні машинного епсилону float64
(~1e-16–2e-16) — набагато нижче порогу 1e-12.

## 4. Чисельна перевірка градієнтів (центральна різниця)

Крок `ε = 1e-6`, критерій `|g_num - g_manual| ≤ 1e-7`, повна навчальна
вибірка (105 обʼєктів), початкові ваги.

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0,0] | -0.0199201843 | -0.0199201844 | 6.03e-11 | Так |
| b1[0] | -0.0705661116 | -0.0705661116 | 3.63e-11 | Так |
| W2[0,0] | 0.1352302086 | 0.1352302087 | 9.22e-11 | Так |
| b2[0] | 0.0855216448 | 0.0855216450 | 1.46e-10 | Так |

Усі різниці на 3–4 порядки нижче допуску 1e-7.

## 5. Дослід із навмисною помилкою (п. 4 завдання)

**Що змінено:** у `dZ2` прибрано ділення на `N`, тобто
`dZ2 = P - Y` замість `(P - Y) / N`. Функція втрат (для звірки значення
втрати) лишається незмінною.

### Прогноз (до запуску)

- **Втрата на тих самих параметрах не зміниться.** Втрата обчислюється
  окремою формулою (`cross_entropy_loss`), яку помилка не зачіпає —
  зламано лише `backward`, а не `forward`/loss.
- **Ненульові градієнти зростуть рівно у N = 105 разів**, оскільки всі
  чотири градієнти (`dW1, db1, dW2, db2`) отримуються ланцюговим правилом
  через `dZ2`, і прибране ділення на `N` — єдина зміна на цьому шляху;
  масштабний множник проходить через усі наступні матричні добутки без
  спотворення напрямку.
- **Обидві перевірки мають це виявити:** звірка з PyTorch (PyTorch
  еталон не змінюється і залишається коректним) і чисельна перевірка
  (формула похідної теж не змінюється) — обидві порівнюють `backward()`
  зі значеннями, що відповідають правильному масштабу, тому різниця
  зросте з ~1e-10…1e-16 до величин порядку самих градієнтів.

### Результат

Втрата дійсно не змінилася: `1.4562007801142816` (NumPy) проти
`1.4562007801142818` (PyTorch) — як і в правильній реалізації.

**Звірка з PyTorch** (критерій `≤ 1e-12`):

| Величина | Максимальна абсолютна різниця | Перевірку пройдено |
|---|---|---|
| Втрата | 2.22e-16 | Так |
| Градієнт W1 | 18.518 | Ні |
| Градієнт b1 | 15.641 | Ні |
| Градієнт W2 | 34.193 | Ні |
| Градієнт b2 | 11.197 | Ні |

**Чисельна перевірка** (критерій `≤ 1e-7`):

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0,0] | -2.0916193547 | -0.0199201844 | 2.0716991703 | Ні |
| b1[0] | -7.4094417164 | -0.0705661116 | 7.3388756047 | Ні |
| W2[0,0] | 14.1991719036 | 0.1352302087 | 14.0639416949 | Ні |
| b2[0] | 8.9797727084 | 0.0855216450 | 8.8942510634 | Ні |

**Зіставлення з прогнозом:** повне підтвердження. Втрата не змінилася.
Відношення "хибного" градієнта до правильного дорівнює точно 105
(наприклад, `-2.0916193547 / -0.0199201843 = 105.000...`), тобто
`N = 105` — розмір навчальної вибірки. Обидві перевірки коректно
провалилися й однозначно вказали б розробнику на пропущене ділення
за нормувальним множником у `backward()`.

**Висновок досліду:** помилку виявлено обома незалежними методами
контролю (autograd-звірка і чисельне диференціювання), значення втрати
саме по собі цю помилку не виявляє — необхідна перевірка градієнтів.

Після досліду коректну реалізацію відновлено (`fix_division=True` —
значення за замовчуванням у `backward()` і в `main.py`).
